## 🎨 UI Context & Design System (Token-Optimized)

### Design system (`frontend/`)

- **Source of truth:** `docs/prototype/clickdummy-editorial.html` ("Editorial"). Spec: `docs/superpowers/specs/2026-10-08-frontend-redesign-design.md`.
- **Tokens:** `frontend/src/theme/tokens.css`, copied from the prototype (`:root` and `:root[data-mode="dark"]`). Paper and ink, one vermilion signal (`--accent`), crimson errors (`--danger`), stage colours `--st-*`, printed-proof colours, ink sidebar `--sb-*`, inverse toasts `--inv-*`. Radii 3/4 px (`--r-ctl`, `--r-panel`), rule width 4 px (3 px on mobile). Theme switch: `data-mode` on `<html>`, preference light/dark/system in localStorage `ajp-theme`, set before first paint by an inline script.
- **Added tokens (not in the prototype):** `--line-control` is the border of interactive controls (input, select, chip, seg) at >= 3:1 against surface, field and bg (`--line-strong` is only about 1.8:1); contrast values are documented next to it. `--sb-danger` is the error colour on the ink sidebar (e.g. the failing-sources badge, always with an icon). Static elements such as `.tag` keep the hairline `--line` (`frontend/src/ui/styles/controls.css`, checked by a unit test).
- **Tailwind v4:** `app/globals.css` maps tokens with `@theme inline` (`bg-surface`, `bg-sunken`, `text-ink`, `text-muted`, `text-faint`, `text-accent`, `text-accent-text`, `border-line`, `bg-st-applied`, `rounded-ctl`, `text-13`, ...). The default palette is removed (`--color-*: initial`), so `indigo-*` and friends do not exist. Use utilities for layout and spacing; use the primitives for controls.
- **Type:** Bricolage Grotesque (variable, `opsz` + `wght`) for titles and meaningful numerals (`.display`, `.mast-title`, `.score-n`), Hanken Grotesk 400/500/600 for UI (body 14.5 px, meta 12-13 px), Source Serif 4 only for A4 documents. Helpers in `frontend/src/theme/base.css`: `.meta` (13 px, meaningful meta text) next to `.small` (12 px, decoration only). Self-hosted via `next/font/local` from `@fontsource`.
- **Primitives (`frontend/src/ui/`):** `Button` (default/primary/ghost/danger, sm, icon-only, busy: spinner, blocks activation, stays focusable via `aria-disabled`), `Tag`, `Chip`, `Seg`, `Field`/`TextField`, `Select`, `CountBadge`, `Notice` (info/warn/error), `ScoreMeter` (bands: Stark >= 80, Möglich >= 60, Schwach), `Masthead` (rule, number, display title, deck), `EmptyState`, `PageSkeleton`, `Tabs`/`TabPanel`, read-only `Stepper` (states past/current/future/skipped/closed, each also as screen-reader text; optional visible heading via `headingLevel`), `Dialog`, `Drawer` (wide/narrow/sheet), `PanelHeader`, `Popover`, toasts via `useToast()`. `MenuButton` (`Menu.tsx`; WAI-ARIA menu with `menuitemradio`, arrow keys, Escape returns focus), `A4Preview` (A4 proof on the desk from a `blob:` PDF URL, open/download fallback without an inline viewer, full-screen dialog on mobile), `Monogram` (company initials, decorative), `Markdown`/`InlineText` (AI text as React nodes: headings, lists, bold, http links only), `Disclosure`, `SelectField`, `TextAreaField`, `CheckField`, `UnsavedChangesProvider` (`setDirty` + `requestLeave` for the leave dialog, `setUnloadWarning` for the browser's close/reload warning only), `SubNav` (links sub-nav with `aria-current`, generic over the section type; Profil and Einstellungen) and `SectionFrame` (focusable h2 plus intro; both pages). Icons: `lucide-react` through `Icon` (stroke 1.75). `Seg` and `Tabs` focus rings are inset so the scroll container does not clip them.
- **Layers:** `ModalLayer` (Dialog, Drawer) and `Popover` share one stack in `src/ui/layerStack.ts`: only the top layer reacts to Escape and Tab, focus returns to the trigger, body scroll lock is ref-counted. Do not add a second overlay mechanism. Stacking order comes from the tokens `--z-drawer-scrim` (50), `--z-drawer` (51), `--z-dialog-scrim` (52) and `--z-dialog` (53) in `tokens.css`, used by `ui/styles/overlay.css`. A dialog (for example the delete confirmation) can open over a drawer, and its scrim (`.scrim:has(+ .dialog)`; `ModalLayer` renders the scrim right before its panel) covers the drawer. Use these tokens for the drawer and dialog layers; never hard-code a z-index for them. Still literals: the popover (60) and the toasts (90) in `overlay.css`, the full-screen A4 preview (`.a4-full`, 51 in `content.css`), the shell bars (30, 40 in `shell.css`) and two local `z-index: 1` stacking fixes.
- **Live regions:** a page (or a modal) has one persistent live region, mounted with it and never conditionally (`role="status"`, `sr-only`). New text is cleared first and set after a short gap: `useClearThenSet(key)` in `frontend/src/ui/useAnnouncement.ts` (`ANNOUNCE_GAP_MS`, 100 ms) is the one implementation, used by `SearchStatus`, `SourcesLiveStatus`, `WizardLiveStatus` and `ProfileLiveStatus`, so an identical message (the same source finishing again, a second link check) is read again. Examples: `SearchStatus` (applications), `SourcesLiveStatus` (crawl ends only, never each step), and inside a modal drawer its own region, because the drawer hides the page's region from screen readers: `WizardLiveStatus` in the add wizard, and a second `SourcesLiveStatus` in the source drawer. While the source drawer is open the page's `SourcesLiveStatus` is `muted` (empty, and an end heard in the drawer is not repeated on the page after it closes), so an end is read once.
- **Gave-up queries (RB13):** `givenUp(query)` in `frontend/src/api/queryState.ts` is the one gate for "show the error, not the skeleton". A query without data that failed, is being retried (`failureCount > 0`) or is paused offline counts as given up, so a section never shows a skeleton through a whole retry backoff. Used by the applications closed count (`settledClosedCount`), the inbox due gate (`useDueGate`) and the source drawer's notifications and run history.
- **Shell:** ink sidebar 252 px with numbered nav (01 Eingang, 02 Bewerbungen, 03 Quellen, 04 Profil), Einstellungen, activity label with "Im Hintergrund" popover (counts crawls only, not job tasks or company research; deviates from spec 4.3 #6 by decision, Q6), user menu (account, language, theme, logout). Below 768 px: bottom bar (Eingang, Bewerbungen, Quellen, Mehr) with the same `NavBadge` as the sidebar: inbox count on Eingang, failing sources on Quellen as a crimson pill (`--sb-danger`, ink alert icon) in the inbox pill's place, with the sentence ("1 Fehler") as screen-reader text; the desktop sidebar keeps icon plus words. While background tasks run, Mehr swaps its icon for the crawl spinner (not pulsing) and adds the screen-reader text "n Aufgaben laufen"; the tasks themselves are in the Mehr sheet. `/` opens global search (ignored inside editable elements). The sidebar foot has a "Suche" button above Einstellungen with the key hint `/` (an `aria-hidden` `kbd`; the button carries `aria-keyshortcuts="/"`), and the Mehr sheet keeps its "Suche" entry. Logout always ends with a full navigation to `/login` (also when the logout call fails), which drops the query cache and closes the socket.
- **Hard rules (spec 5):** no gradients, glassmorphism, indigo/purple, emoji, sparkle or rainbow icons, pulsing dots (the crawl spinner is the one allowed motion indicator). Vermilion only for the next move, the active nav item, strong scores and primary buttons. Errors: crimson plus icon plus words. Text contrast >= 4.5:1, control borders >= 3:1. Hit targets >= 44 px on mobile (checkbox rows, `.check`, are 44 px at every width), meta text >= 13 px where it carries meaning, visible focus rings, no nested interactive elements.
- **Toasts:** inverse ink pill, at most 2, 6 s (10 s with an action such as undo), paused on hover/focus; the undo toast is the last tab stop, so a keyboard user in a long list may not reach it in time (accepted, Q2: the recovery path is "Von dir aussortiert" and Bewerbungen). Two persistent live regions: `role="status"` for info/success, `role="alert"` for errors, so announcements work even for the first toast.
- **States:** loading = skeleton (no whole-page spinners), empty = copy from the prototype, error = message plus retry via `describeError`. `describeError` gives a generic translated sentence per error code; server `detail` is shown only through an explicit per-call mapping, never by default.
- **Job page (`/jobs/[id]`):** header (monogram, title, meta, posting link, big score; `.recede` from Beworben on), phase track plus "Phase ändern" menu with all guards, two columns at >= 1024 px (tabs left, sticky 360 px "Nächster Schritt" + "Termine & Daten" right), single column below (header, next card, tabs). Tabs live in `?tab=` (passung, unterlagen, firma, interview, verlauf). Generation entry points use one verb family: "Erstellen" / "Neu erstellen", each with an optional "Hinweis an die KI". Background tasks show text progress (`TaskState`), never percentages; cancel only for generation. The nav highlights Eingang for matches and sorted-out jobs, Bewerbungen otherwise. Unterlagen: A4 proof from the PDF blob, "Bearbeiten" opens the sandboxed HTML editor on the sheet (links in the app ask before unsaved edits are lost). Firma: shared-profile notice, "Stimmt die Web-Adresse?" before the first research. Interview: AI levels are translated, unknown ones shown raw. Verlauf: notes autosave without a Save button (error shown inline, toast after leaving), to-dos save one after the other.
